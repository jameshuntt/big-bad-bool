# Changelog

## 0.1.2 (2026-11-07): big-bad-bool big-bad-bool-derive

- `big_bad_bool::program`: the facade can carry the published `big-bad-bool-program` 0.1.0 crate, re-exported whole, behind the `program` feature ([crates/big-bad-bool/src/lib.rs @ 7e4a6bc](https://github.com/jameshuntt/big-bad-bool/blob/7e4a6bc92c99304c569ae31af94249f272cf9921/crates/big-bad-bool/src/lib.rs#L21-L26)). The dependency is optional and off by default ([crates/big-bad-bool/Cargo.toml @ 7e4a6bc](https://github.com/jameshuntt/big-bad-bool/blob/7e4a6bc92c99304c569ae31af94249f272cf9921/crates/big-bad-bool/Cargo.toml#L14)), so a build without the feature has the same dependency graph as 0.1.1.
- Two features, neither default ([crates/big-bad-bool/Cargo.toml @ 7e4a6bc](https://github.com/jameshuntt/big-bad-bool/blob/7e4a6bc92c99304c569ae31af94249f272cf9921/crates/big-bad-bool/Cargo.toml#L16-L20)): `program` builds on the workspace rust-version, 1.85; `program-bowl` also turns on the program crate's `bowl` feature, the ob-serve-a-bowl adapter (`BowlObserver`), and needs Rust 1.88 because ob-serve-a-bowl does. docs.rs builds with `program`.
- `program-bowl` resolves ob-serve-a-bowl 0.2.3. ob-serve-a-bowl 0.2.2 depended on the big-bad-bool facade ([Cargo.lock @ 7e4a6bc](https://github.com/jameshuntt/big-bad-bool/blob/7e4a6bc92c99304c569ae31af94249f272cf9921/Cargo.lock#L272-L277)), so a crates.io build of this facade with `program-bowl` would have had the facade depend on itself through big-bad-bool-program and ob-serve-a-bowl. 0.2.3 depends on big-bad-bool-core and big-bad-bool-derive instead ([ob-serve-a-bowl Cargo.toml @ d087e96](https://github.com/jameshuntt/ob-serve-a-bowl/blob/d087e96f65c058dbf175f8c4aa111d1888bfc94e/Cargo.toml#L27-L29)), and `cargo tree -p big-bad-bool --features program-bowl -i big-bad-bool` prints only the facade itself.
- The workspace patches big-bad-bool-core and big-bad-bool-interact to the copies here ([Cargo.toml @ 7e4a6bc](https://github.com/jameshuntt/big-bad-bool/blob/7e4a6bc92c99304c569ae31af94249f272cf9921/Cargo.toml#L19-L24)) so that, inside this repo, big-bad-bool-program from crates.io and the facade see one big-bad-bool-core and one `PackedWord`. The patch is in the workspace manifest, which is not packaged; the published facade's manifest has only version requirements.
- `#[bitpack]` and the core metadata are unchanged. Proved by `crates/big-bad-bool/tests/facade.rs` (the root names with any feature set) and `crates/big-bad-bool/tests/program.rs` (the program crate through the facade: a program with no framing builds, verifies and steps on 1.85, and with `program-bowl` the Bowl adapter changes no result), on Rust 1.85 and stable in CI.
- Both packages now declare `rust-version = "1.85"` ([crates/big-bad-bool-derive/Cargo.toml @ fbd68cb](https://github.com/jameshuntt/big-bad-bool/blob/fbd68cb71f61ed6fc68b564a394d463cd0708a21/crates/big-bad-bool-derive/Cargo.toml#L5)) and carry LICENSE-MIT and LICENSE-APACHE, the license the manifests already stated ([a577bc2](https://github.com/jameshuntt/big-bad-bool/commit/a577bc28d2a2c63fe3c9127ad83093017040a317)). 0.1.1 had neither.
- big-bad-bool-derive: no code change. It shares the workspace version with the facade, so it is republished as 0.1.2; `diff -r` of the published 0.1.1 package's `src` against `crates/big-bad-bool-derive/src` prints nothing.
